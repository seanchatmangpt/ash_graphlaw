# HANDWRITTEN

Ledger of every hand-written element that no pack capability emits. Each file carries the header
`# UNSUPPORTED(generator-capability): <reason>`. The machine copy is the `glx:UnsupportedResidue`
rows in `ontology.ttl` (gates/060); `scripts/ggen_sync.sh --check-ledger` requires every
`glx:residuePath` to appear in this file. Generated files are never hand-edited; see
`scripts/ggen_sync.sh --list-projections`.

## Generated files with a recorded residue

These paths are projections and stay generated; the residue is recorded, never hand-edited.

- `lib/mix/tasks/ash_graphlaw.install.ex`: the pack installer inserts the bare text
  `extensions: [AshGraphLaw.Resource]` with `Igniter.Code.Common.add_code/3`, which parses a
  statement, so `--target` raises `SyntaxError` (pack defect observed at pack sha caa4fe61). The
  fix belongs in `ontology.ttl` (aex installer target-mode individuals per pack
  `gates/060_installer_target_mode_contract.rq`). The row is removed once the template emits
  `add_extension/1` correctly.
- `lib/ash_graphlaw/info.ex`: generated by the pack `info.ex.tmpl`; missing typespecs or docs
  beyond the template are residue. A superseded ledger path spelling, `lib/ash_graphlaw/resource/info.ex`,
  is kept here so an older ontology row still resolves.
