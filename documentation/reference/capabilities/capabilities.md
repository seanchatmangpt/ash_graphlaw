# capabilities

Report ABI version, crate version, semantic authorities, dialects, ops and registry digests.

- Wire operation: `capabilities` (registry order 1).
- Typed module: `AshGraphLaw.Capability.Capabilities`.
- Typed API: `AshGraphLaw.Capability.API.capabilities/2` and `capabilities!/2`.
- Result: `AshGraphLaw.Result.Capabilities`.

## Usage

```elixir
{:ok, result} = AshGraphLaw.Capability.API.capabilities([])
```

`run/2` accepts the options of `AshGraphLaw.call/2` (server, timeouts, fuel). The request is
built and validated client-side without the engine; the call itself runs on the real engine.

This operation takes no request fields.

## Refusals

Refusal kinds: `ResourceLimit`, `Unsupported`.

Refusal detail codes: `ResourceLimit`.

Client-side, a bad request refuses with `:invalid_capability_request` before the engine is called.
A refusal is an observation about one exact input and never grants authority.
