# hooks

Materialize a knowledge-hook pack over a dataset.

- Wire operation: `hooks` (registry order 12).
- Typed module: `AshGraphLaw.Capability.Hooks`.
- Typed API: `AshGraphLaw.Capability.API.hooks/2` and `hooks!/2`.
- Result: `AshGraphLaw.Result.Hooks`.

## Usage

```elixir
{:ok, result} = AshGraphLaw.Capability.API.hooks([pack: "...", data: "..."])
```

`run/2` accepts the options of `AshGraphLaw.call/2` (server, timeouts, fuel). The request is
built and validated client-side without the engine; the call itself runs on the real engine.

## Request fields

| Field | Type | Required | Nullable | Default | Description |
|---|---|---|---|---|---|
| `pack` | `data_spec` | true | false | none | Hook pack as a data spec (kh: vocabulary). |
| `data` | `data_spec` | true | false | none | Data to operate on: an object {text, dialect?, hint?, base?}; the dialect is sniffed when omitted. |

## Response

Untagged response.

| Field | Type | Required | Nullable | Description |
|---|---|---|---|---|
| `id` | `string` | true | false | Content-addressed id of the materialized state. |
| `rounds` | `integer` | true | false | Fixpoint rounds executed. |
| `quads` | `integer` | true | false | Quad count of the materialized state. |
| `nquads` | `string` | true | false | Materialized state as N-Quads. |
| `firings` | `list<object>` | true | false | Hook firings: {hook, round, added, row}. |

The decoded result also carries `:raw`, the entire response map, so no engine field is lost.

## Refusals

Refusal kinds: `Ambiguous`, `EngineRejected`, `NotSemanticContent`, `ResourceLimit`, `Unsupported`.

Refusal detail codes: `ResourceLimit`.

Client-side, a bad request refuses with `:invalid_capability_request` before the engine is called.
A refusal is an observation about one exact input and never grants authority.
