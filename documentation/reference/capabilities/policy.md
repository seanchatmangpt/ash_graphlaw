# policy

Admit a FOND policy as strong-cyclic against a planning problem.

- Wire operation: `policy` (registry order 14).
- Typed module: `AshGraphLaw.Capability.Policy`.
- Typed API: `AshGraphLaw.Capability.API.policy/2` and `policy!/2`.
- Result: `AshGraphLaw.Result.Policy`.

## Usage

```elixir
{:ok, result} = AshGraphLaw.Capability.API.policy([problem: "...", policy: "..."])
```

`run/2` accepts the options of `AshGraphLaw.call/2` (server, timeouts, fuel). The request is
built and validated client-side without the engine; the call itself runs on the real engine.

## Request fields

| Field | Type | Required | Nullable | Default | Description |
|---|---|---|---|---|---|
| `problem` | `json_or_string` | true | false | none | Planning problem as a JSON object or JSON text. |
| `policy` | `json_or_string` | true | false | none | Policy as a JSON object, entries array or JSON text. |

## Response

Untagged response.

| Field | Type | Required | Nullable | Description |
|---|---|---|---|---|
| `initial_states` | `list<string>` | true | false | Initial states of the problem. |
| `reachable` | `list<string>` | true | false | States reachable under the policy. |
| `goal_states` | `list<string>` | true | false | Reachable goal states. |
| `entries` | `list<list<string>>` | true | false | Admitted policy entries as [state, action]. |
| `ntriples` | `string` | true | false | Admitted policy as N-Triples. |

The decoded result also carries `:raw`, the entire response map, so no engine field is lost.

## Refusals

Refusal kinds: `EngineRejected`, `ResourceLimit`, `Unsupported`.

Refusal detail codes: `PolicyRefused`, `ResourceLimit`.

Client-side, a bad request refuses with `:invalid_capability_request` before the engine is called.
A refusal is an observation about one exact input and never grants authority.
