# mix_tasks

The mix tasks and repository scripts this package ships or uses. Provenance is in the
[support matrix](support_matrix.md).

## `mix ash_graphlaw.vendor`

Vendors the pinned engine into `priv/graphlaw/graphlaw.wasm`.

| Invocation | Effect |
|---|---|
| `mix ash_graphlaw.vendor` | downloads artifact.url from priv/graphlaw/MANIFEST.json over HTTPS |
| `mix ash_graphlaw.vendor --from PATH` | uses a local file instead of downloading |
| `mix ash_graphlaw.vendor --check` | verifies the vendored file against the pin; writes nothing |

A candidate is written to a temporary file next to the target, re-read and re-hashed, then renamed
over the target, and only when its sha256 equals `artifact.sha256`. On any mismatch it is discarded,
an existing vendored engine is left untouched, and the task exits non-zero (`wasm_digest_mismatch`).
Other failures: `wasm_unreadable`, `wasm_invalid` (manifest), `wasm_not_vendored` (`--check`).

## `mix ash_graphlaw.verify`

Admits the vendored engine through `AshGraphLaw.EngineLoad.admit/2` (digest pin, import allowlist,
required exports), starts a real host, sends the `capabilities` op and requires the reported
`abi_version` to equal the manifest's. Exits non-zero with a typed code on any refusal. A pass is an
observation about those bytes and grants nothing.

## `mix ash_graphlaw.mutate`

The anti-vacuity mutation court; see [Run the mutation catalog](../how_to/run_the_mutation_catalog.md).
Options: `--only ID` (repeatable), `--evidence-dir DIR`, `--list`, `--require-killed`. Run it with
`MIX_ENV=test`.

## `mix ash_graphlaw.parity`

The capability parity court. Loads the generated registry, starts a real host over the vendored
engine, sends `capabilities`, and runs checks `P1` to `P9` and `R1` (see `AshGraphLaw.Parity`).
It never skips. Run `mix ash_graphlaw.vendor` first.

| Invocation | Effect |
|---|---|
| `mix ash_graphlaw.parity` | run all checks, print `id status title` per check |
| `mix ash_graphlaw.parity --evidence-dir DIR` | also write `DIR/parity_report.json` (canonical JSON), on pass and on refusal |
| `mix ash_graphlaw.parity --list` | print check ids and titles; no engine is loaded; exit 0 |
| `mix ash_graphlaw.parity --no-examples` | P9 is reported not_run, never pass |
| `mix ash_graphlaw.parity --wasm PATH` | use other engine bytes (unpinned) |

Failure raises `Mix.Error` with a bracketed code: `[capability_parity_drift] <check ids>`,
`[wasm_not_vendored]`, `[invalid_options]`, `[evidence_unwritable]`, or another refusal code that
blocked the run. A pass is `PARTIAL_ALIVE` for that engine and registry. Against the `v26.9.28`
pin, drift is possible until the pin moves to a release carrying the registry.
See [run the parity court](../how_to/run_the_parity_court.md).

## `mix ash_graphlaw.install`

An Igniter installer, generated by `ash-extension-pack`: adds the `wasmex` dependency and the
`AshGraphLaw.Formatter` plugin. `--target Module` is meant to patch a resource; in the pinned pack
version it raises a `SyntaxError`. `UNSUPPORTED(generator-capability)`, pinned by
`test/mix/tasks/ash_graphlaw_install_test.exs`.

## `mix spark.cheat_sheets`

Writes `documentation/dsls/DSL-AshGraphLaw.Resource.md` from the compiled extension (alias in the
generated `mix.exs`).

## `scripts/vendor_registry.sh`

`scripts/vendor_registry.sh [--check] [--from DIR]` copies `capability-registry.json`,
`capability-registry.ttl` and `op-examples.json` from `../graphlaw/registry` (or `--from DIR`,
or `GRAPHLAW_REGISTRY_DIR`) into `priv/graphlaw/`. It recomputes `registry_sha256` and
`surface_sha256` with the canonical-JSON digest rule and refuses a copy that differs from the
digests the file declares. `--check` writes nothing and exits 1 on a difference.

## `scripts/import_registry.sh`

`scripts/import_registry.sh [--check]` splices the registry TTL statements into `ontology.ttl`
between `# BEGIN GENERATED-REGISTRY sha256:<registry_sha256>` and `# END GENERATED-REGISTRY`, and
rewrites `glx:registrySha256`. Idempotent. `--check` writes nothing and exits 1 on a difference.

## `scripts/vendor_marketplace.sh`

Materializes `vendor/ggen-marketplace/packs/` (`ash-extension-pack` and
`graphlaw-ash-capability-pack`) from the exact marketplace sha
pinned in `ontology.ttl` (`glx:marketplaceSha`) with `git archive` (no clone, no worktree), and
records the sha in `vendor/ggen-marketplace/.pin`. The source repository is `~/ggen-marketplace`,
or `GGEN_MARKETPLACE_REPO`.

## `scripts/ggen_sync.sh`

The manufacturing entry point. Flags: `--check` (sync twice, compare), `--check-ledger`,
`--check-versions`, `--list-projections`, `--help`. Refuses a vendored marketplace whose recorded sha differs from
`ontology.ttl`, removes this package's previous pack projections, runs `ggen sync run`, deletes the
projections that belong to the pack's reference specs, and runs `mix format`.

| Exit | Meaning |
|---|---|
| 0 | synced and formatted |
| 2 | `vendor/` missing |
| 3 | pin mismatch between ontology.ttl and vendor/ggen-marketplace/.pin |
| 4 | `ggen sync run` failed |
| 5 | `mix format` failed |
| 6 | non-deterministic projections (`--check`) |
| 7 | ledger gap (`--check-ledger`) |
| 8 | version drift (`--check-versions`) |
| 64 | usage |
